# Week 2 Pilot: Spatial Data, Labels, Bias, and Evaluation

## Purpose

Use Week 2 to validate the complete production system before scaling it to the rest of the course.

## Existing inputs

- Active E16 syllabus
- Research-complete lecture content blueprint
- Draft Week 2 lecture
- Draft Week 2 student lab
- Week 2 instructor guide and lecture plan
- Active lecture and laboratory templates
- Course glossary, ArcGIS Pro quick reference, responsible GeoAI reference, and data sources guide

## Target learning outcomes

Students should be able to:

1. Explain why labels and reference data are interpretations rather than unquestionable truth.
2. Identify spatial leakage, sampling bias, and scale mismatch in a GeoAI evaluation.
3. Interpret a confusion matrix, user's accuracy, and producer's accuracy.
4. Map error patterns and judge whether a result is fit for a stated environmental use.

The Pedagogy Architect must confirm or revise these outcomes before production.

## Required pilot outputs

- Evidence pack and claim-to-source matrix
- Approved instructional blueprint
- 50-to-65-slide lecture deck with speaker notes
- Two-hour no-code ArcGIS Pro laboratory
- Prepared project, data, and expected outputs
- Instructor guide, troubleshooting guide, answer key, and rubric
- Student simulation and timing report
- Visual design and accessibility report
- Independent critic report
- Novice human pilot report
- Final approved and published package

## Pilot success criteria

- Lecture fits 55 minutes with active-learning pauses.
- Laboratory fits 100 planned minutes, leaving 20 minutes for discussion and recovery.
- A novice human completes the laboratory on a standard GsAL workstation.
- No step requires programming.
- No critical or major critic findings remain open.
- All source, image, software, dataset, and model metadata are recorded.
- All external dependencies have tested fallbacks.
- David approves the final package.

## Measurements to capture

- Agent runtime by stage
- Cloud-model cost by stage and provider
- Local-model usage
- Number and severity of critic findings
- Number of revision loops
- Human review time
- Student pilot completion time
- Failures attributable to instructions, data, accounts, software, or infrastructure

The pilot review determines whether to scale the workflow unchanged, revise it, or simplify it.
