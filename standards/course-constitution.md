# E16 GeoAI Course Constitution

## Purpose

E16 GeoAI for Environmental Science is an eight-class applied introduction to artificial intelligence for spatial and environmental problem solving. It serves students and professionals with little or no programming experience.

This file defines binding design constraints for every agent and workflow. Changes require David Saah's explicit approval.

## Immutable course constraints

- Eight class meetings
- Three hours per class
- Approximately one hour of lecture
- Approximately two hours of guided laboratory work
- Approximately one hour per lecture; current red-team-validated decks run 55 to 64 minutes
- No programming required at any point
- No student writing, editing, or executing code
- ArcGIS Pro is the primary GIS and independent validation environment
- Browser-based tools are preconfigured or instructor-provisioned
- Environmental and real-world applications anchor every class
- Responsible AI, uncertainty, and independent verification appear throughout
- Weeks 1 through 7 have self-contained laboratory outcomes
- The final project is bounded, introduced, completed, and presented in Week 8
- Every external service has a documented fallback

## Weekly sequence

### Week 1: Course Overview and the GeoAI Landscape

Relationships among GIS, spatial analysis, machine learning, deep learning, foundation models, generative AI, and agents. Laboratory: GeoAI Systems Detective.

### Week 2: Spatial Data, Labels, Bias, and Evaluation

Data quality, scale, resolution, labels, sampling, spatial dependence, accuracy, bias, uncertainty, and fitness for use. Laboratory: Label and Accuracy Detective.

### Week 3: Machine Learning and Deep Learning for Environmental Mapping

Supervised and unsupervised learning, decision trees, random forests, neural networks, image classification, object detection, segmentation, transfer learning, and pretrained models. Laboratory: Classify, Detect, and Compare.

### Week 4: Geospatial Foundation Models

Embeddings, multimodal and multitemporal Earth observation, similarity search, change detection, sparse labels, AlphaEarth Foundations, OlmoEarth, transferability, and local validation. Laboratory: Earth Embedding Explorer.

### Week 5: Large Language Models for Geospatial Reasoning

Context, retrieval, grounding, prompt structure, geospatial strengths and failures, privacy, citations, calculations, and verification. Laboratory: Spatial Assistant and Auditor.

### Week 6: Agentic Geospatial Analysis

Agents, project instructions, plan-first work, permissions, execution, testing, iteration, cost monitoring, and human oversight. Ujaval Gandhi's Spatial Thoughts course provides the practical backbone. Laboratory: Plan, Direct, and Validate.

### Week 7: Skills, MCP, Automation, and Reproducible GeoAI

Reusable skills, persistent instructions, tools, resources, prompts, MCP architecture, authorization, secrets, security boundaries, reproducibility, and failure recovery. Laboratory: Tool-Connected GeoAI.

### Week 8: Mini-Capstone and Course Synthesis

Method selection, claim discipline, professional communication, environmental responsibility, and next steps. Laboratory: Environmental GeoAI Mini-Capstone.

## Recurring verification framework

Every class must reproduce these questions exactly:

1. What do the data actually show?
2. What does the model or agent produce?
3. What does a human infer from that output?
4. What evidence is needed before the inference can guide action?

## Required class package

Every week must contain:

- Approved evidence pack
- Approved instructional blueprint
- 50-to-65-slide lecture with speaker notes and source references
- Two-hour guided laboratory
- ArcGIS Pro project specification and data manifest
- Instructor guide and troubleshooting guide
- Student worksheet and submission template
- Answer key and grading rubric
- Verification and responsible-use exercise
- Accessibility report
- Student simulation report
- Human pilot report
- Independent critic report
- AI-use and provenance log
- Published version record

Lab packages also follow `14_LAB_PACKAGE_STANDARD.md` in the authoritative Drive: no student code, an honest two-hour time budget, real data where available, explicit `STUDENT DECIDES / SOFTWARE PERFORMS AUTOMATICALLY / YOU MUST VERIFY` roles, an AI-Use Log, a reproducibility record, the Ethics Checkpoint Card, computed answer values, and a fallback for every live service.

## Human authority

- Agents may propose changes but cannot alter the constitution.
- Agents cannot approve their own work.
- A simulated student cannot replace a novice human pilot.
- David Saah has final academic and publication authority.
